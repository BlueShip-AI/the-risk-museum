Neural Pricing: Data Density, Not Model Capacity, Governs When
Neural Networks Beat Parsimonious Volatility Econometrics

V. Dimopoulos
BlueShip Research
Working Paper No. 2 · 13 July 2026

In one line: My neural network lost to a simple 1993 formula when data was scarce, and won when data was plentiful.

Abstract. I test whether a neural network improves on parsimonious econometric models for volatility one day ahead. A small multilayer perceptron (~2,000 parameters), forecasting the range one day ahead from a fixed information set plus state components on dealer positioning, is evaluated over the same out-of-sample window of 1,794 days and the same gates as its competitors. It loses significantly: the mean absolute error of the best network is 58.9 basis points, against 41.2 for a linear HAR + VIX + GJR ladder and 41.6 for GJR-GARCH, a model of four parameters from Glosten, Jagannathan, and Runkle (1993), with a Newey–West t of −4.37 on the error differential over roughly 3,500 daily observations. The identical architecture family, applied instead to approximating the Heston (1993) pricing map from 9,000 self-generated surfaces of implied volatility, clears every gate (accuracy of 0.23 volatility points, ~45,000x speedup, correct skew). Data density, not model capacity, governs the outcome.

Keywords: neural networks, volatility forecasting, GJR-GARCH, HAR, Heston model, deep learning volatility, data efficiency, model parsimony.

1. Introduction

A prior note in this series found that GJR-GARCH, the asymmetric volatility model with four parameters from Glosten, Jagannathan, and Runkle (1993), outperformed a Markov model of my own construction that switches between states. Nonlinear interactions are precisely what a linear recursion cannot represent, which motivates the present question: can a neural network do better? This note, the first on neural pricing, reports two experiments run under identical out-of-sample discipline and reaches opposite verdicts.

2. Method

I trained a small multilayer perceptron (~2,000 parameters) to forecast the range one day ahead from the same information set as the linear models, augmented with the state components on dealer positioning. Training was walk-forward with monthly refits, ensembles of three seeds, and early stopping, evaluated on the same out-of-sample window of 1,794 days and the same gates applied to every other forecaster.

3. Results

3.1 Daily volatility forecasting

Table 1 reports out-of-sample mean absolute error. The network failed to win, and lost significantly: the Newey–West t-statistic on the error differential is −4.37. A model of roughly 2,000 parameters was beaten by one of four, on approximately 3,500 daily observations. The state inputs helped the network (58.9 against 63.4 basis points), consistent with prior measurements of dealer positioning, but no adjustment rescued the architecture at this data scale. Volatility measured daily yields about 250 observations per year, which is starvation for a neural network and ample for a parsimonious recursion.

3.2 Approximating the option surface

I then applied the same architecture family to a different task: approximating the pricing map of the Heston (1993) stochastic volatility model, following the Deep Learning Volatility approach of Horvath, Muguruza, and Tomas (2021). Training used 9,000 surfaces of implied volatility generated by the model itself, a dense and effectively unlimited sample. Against pre-set gates the approximation passed on every axis (Table 2).

4. Discussion

The architecture family was identical; the verdicts were opposite. Neural capacity is not a modular upgrade to a forecast. It adds information where data is dense and structured (an option surface is thousands of simultaneous quotes linked by arbitrage) and loses to econometrics from forty years ago where data is scarce and noisy. A neural network fitted to a single daily time series reproduces the 63.4 basis points of Table 1, not the 0.23 volatility points of Table 2.

The first run of the Heston laboratory failed: every implied volatility pinned at exactly 150%, the result of a bisection bug on one line of my own inversion code. A test of the degenerate case caught it, since vol-of-vol → 0 must recover Black–Scholes exactly, which the corrected code then did to four decimals. The failure was indistinguishable from a result until the test caught it.
